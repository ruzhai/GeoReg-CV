### 第二阶段：时间对齐与轨迹补偿 【TODO】

阶段负责人：B

阶段目标： 研究非规则时延条件下的时间对齐与轨迹预测补偿，形成第一个完整的算法模块。

<!-- 表 4 -->
| 人员 | 具体任务 |
|---|---|
| A | 负责实验框架、算法接口和测试脚本，保证时延仿真、轨迹预测与后续系统接口一致 |
| B | 主导时间对齐算法研究，完成运动状态模型、卡尔曼滤波、非规则采样处理及轨迹补偿算法的设计与改进 |
| C | 研究时间错位对空间定位的影响，设计时间误差如何转化为目标位置误差的仿真实验，同时继续推进空间配准基准复现 |
| D | 开发时延参数设置和轨迹可视化功能，展示原始观测轨迹、补偿轨迹和参考真值，自动生成实验结果图表 |

核心实验建议：

先实现三个算法进行比较：

不进行时间补偿，直接使用当前收到的数据；

使用线性插值、匀速运动预测等基础方法；

使用考虑不规则采样间隔的卡尔曼滤波或改进方法。

分别在100、300、500和800 ms等延迟条件下测试目标位置误差。

重点不能只是展示轨迹变平滑了，而要与已知真值比较，证明补偿后的目标位置更准确。

阶段成果： 时间对齐算法模块、时延与轨迹误差对比曲线、实验报告。

### 第三阶段：跨视角空间配准研究 【TODO】

阶段负责人：C

这一阶段建议投入最多的算法研究精力，因为姿态先验辅助跨视角配准是当前最值得重点挖掘的创新方向。

<!-- 表 5 -->
| 人员 | 具体任务 |
|---|---|
| A | 将时间对齐模块接入空间配准实验框架，负责数据接口、自动批量测试和算法性能记录 |
| B | 负责姿态与时间数据预处理，模拟IMU姿态测量误差，开展不同姿态误差下的配准鲁棒性分析 |
| C | 主导跨视角算法，研究姿态辅助几何校正、特征提取、图像匹配以及误匹配剔除，完成改进方法 |
| D | 负责数据集图像配对整理、配准标注检查与可视化展示，开发匹配点、对应区域和配准前后图像对比功能 |

建议设计三组核心实验：

<!-- 表 6 -->
| 实验组 | 方法 |
|---|---|
| 方案1 | 原始图像直接匹配 |
| 方案2 | 姿态先验校正 + 图像匹配 |
| 方案3 | 姿态先验校正 + 图像匹配 + 几何一致性约束 |

比较三种方法在不同视角差异、姿态噪声和图像质量条件下的效果。

这里要避免一个技术误区：图像检索成功不等于空间几何配准成功。对于真正的配准实验，需要有可靠的匹配点、区域对应或位置真值。

#### 同期安排一次小规模实飞预实验

如果实验室有现成无人机，可在这一阶段安排一次受控数据采集，不必等到所有算法完成。

建议由具备相应飞行资格和经验的人员负责飞行，四名项目成员主要负责：

A：实验组织、拍摄清单和数据归档。

B：采集时间记录、时间戳校验。

C：相机标定、姿态记录、参考标志物布设。

D：地面观测数据采集与数据质量检查。

地面端使用固定相机或专门的观察终端即可，救援人员作为救援角色，不承担额外的观测任务。

阶段成果： 空间配准算法、姿态先验有效性实验、初步实飞数据、空间配准评测报告。

### 第四阶段：轻量化目标重识别与时空联合关联 【TODO】

阶段负责人：D

阶段目标： 让系统不仅能够找到同一位置，还能够在不同视角中判断同一个目标的身份。

<!-- 表 7 -->
| 人员 | 具体任务 |
|---|---|
| A | 负责三个算法模块的数据连接和端到端测试，检查跨模块输出是否完整、准确 |
| B | 设计时间一致性评分机制，将轨迹补偿和运动预测信息用于目标身份关联 |
| C | 设计空间一致性约束，将配准结果用于筛选不合理的跨视角目标匹配，并负责该部分消融实验 |
| D | 主导轻量化ReID模型训练和优化，完成跨视角特征提取、相似度匹配、身份关联以及参数量和推理速度测试 |

这一阶段最重要的是研究：如果只依靠视觉特征无法准确识别同一目标，加入时间和空间约束以后能否改善关联效果？

建议采用以下实验方案：

<!-- 表 8 -->
| 对比方法 | 研究作用 |
|---|---|
| 仅使用视觉特征 | ReID基准 |
| 视觉 + 时间约束 | 验证时间对齐贡献 |
| 视觉 + 空间约束 | 验证空间配准贡献 |
| 视觉 + 时间 + 空间 | 验证联合方法效果 |

注意，人员和车辆的ReID需要各自具有实例身份标注的数据，不能把目标分类正确率直接当作身份重识别准确率。

阶段成果： 轻量化ReID模块、联合关联算法、模型效率测试及消融实验报告。

阶段负责人：A

这个阶段四个人的分工不再按照单个算法划分，而是围绕真实数据采集、系统运行和实验展示重新组织。

<!-- 表 9 -->
| 人员 | 具体任务 |
|---|---|
| A | 负责系统总体集成、算法接口联调、实验组织和运行稳定性测试 |
| B | 负责无人机及地面数据时间管理、传输延迟记录、实时或离线时间补偿验证 |
| C | 负责实飞场景设计、相机标定、无人机姿态数据整理、真实跨视角匹配与定位误差评测 |
| D | 负责可视化系统完善、ReID推理接口、目标身份显示、人工修正及操作流程 |

这一阶段建议分两次测试。

第一次：离线实飞实验。 无人机和地面相机分别采集同一场景图像，将数据导入电脑，验证姿态辅助空间配准。重点确保数据真实、能够标注真值、结果可复现。

第二次：系统级协同实验。 在条件允许的情况下接入实时视频或数据传输，将时间补偿、图像匹配、目标关联及结果展示连接起来。网络延迟和计算性能需要实际测量，不能把离线推理结果等同于实时运行性能。

如果增加机载计算机，可以将轻量化特征提取或目标检测作为扩展实验，但不必把整套算法全部部署到无人机上。

这一阶段最终必须形成的演示场景

无人机和地面相机观察同一个实验区域。

系统导入或接收两路图像及时间信息。

展示时间错位与补偿前后的轨迹。

展示跨视角图像匹配及空间对应关系。

关联不同视角中的同一目标。

在界面中展示统一结果，并允许人工修正。

这里最重要的是让四个部分真正连接，而不是仅把三个独立算法的图片放在同一个页面。

## 五、实际推进中，需要建立哪些协作机制？

### 1. 每周开展一次内部验收

本段已经完成哪些功能和实验；

产生了哪些可运行代码和可查看结果；

当前存在什么数据或算法问题；

下一阶段需要其他成员提供什么接口或数据。

每次汇报最好都能现场运行一段程序或展示一组可复现的实验。

### 2. 设置四个关键检查节点

基础环境验收

三个基准算法能够运行，数据格式和评测协议确定。

核心算法验收

时间补偿和姿态辅助配准具有定量结果，明确实飞是否可行。

完整算法链验收

三个模块能够通过统一接口传递数据，完成端到端离线示例。

系统演示验收

可视化平台完成，具备可重复运行的真实或仿真实验案例。

## 六、项目可能遇到的三个关键风险

第一个风险：空间配准难度超过预计。 Ground–Drone跨视角数据的真实几何对应关系不一定完整，现有深度匹配网络也不一定能够处理极端视角。建议先建立场景检索基准，再在可靠对应的图像子集上验证精细配准，不要一开始就要求所有图像完成像素级匹配。

第二个风险：三个算法使用不同的数据集。 时间补偿、空间匹配和ReID可能需要三套不同标注。早期可以独立验证，但后期必须准备一个统一的小规模演示案例。这个案例既可以采用真实采集与补充标注，也可以采用清楚标识的仿真数据。

第三个风险：实飞和机载部署占用过多精力。 如果机型选购、数据接口和飞行准备耗费大量时间，会影响主要算法研究。建议先完成离线实飞验证；实时传输与机载部署作为条件允许时的扩展目标。
